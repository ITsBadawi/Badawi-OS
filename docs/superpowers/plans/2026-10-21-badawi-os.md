# Badawi OS Implementation Plan

**Goal:** Build the owner's desktop application using the approved Arabic visual direction and local-first specification.
**Architecture:** Sandboxed React renderer, narrow validated IPC, a Node host, SQLite transactions, deterministic engine and a single bounded job at a time. Providers have no filesystem or command authority.
**Tech Stack:** Electron, React, TypeScript, SQLite, Luxon, Zod. Pinned dependencies and lockfile.
**Spec:** ../spec/02-DECISIONS-AND-SCOPE.md through 15-OFFICIAL-SOURCES.md; ../../../../Badawi-OS-Design-Preview.html.
**Authorization:** The owner explicitly instructed this agent to build the application on 2026-10-21. Implement natively in this session; no redundant milestone approval. Account connections and paid live requests require user action within the resulting app.

## Global constraints
- No Docker, rented server, permanent HTTP listener, general terminal or source-code writing tools.
- Arabic RTL UI, English source/docs. Stopped on launch, Gaming independent of mode.
- Source roots read-only; secret exclusions, no symlink traversal; native selection only.
- Google Drive is the only cloud backup destination. Never claim upload/restore without verification.
- No real keys or sample success states. All external sending requires an exact payload preview.

## Review focus
- Mode changes during asynchronous operations: close admission before abort, preserve unknown outcomes.
- Source-path traversal, links and secret filenames: fail closed and never execute repository code.
- Restart/clock jumps: deduplicate occurrences, bounded catch-up, Stopped recovery.
- Renderer compromise: validate request and sender; no secrets returned to renderer.
- Interrupted network/backup writes: preserve earlier state and require verification.
