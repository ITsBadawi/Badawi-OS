## Engine contract
requestedMode = Running/Pause/Stop; effective states include Pausing/Stopping. Close admission and increment epoch transactionally before acknowledging a mode change. Reject claims/steps using an obsolete epoch. Already-started work reaches the nearest safe boundary. Never show Paused, Stopped, or gamingQuiescent before relevant workers actually stop.
Pause checkpoints work and keeps only a lightweight coordinator. Stop drains and shuts down workers and scheduler timers while retaining the UI. Run Now never bypasses these policies. Auto-start and tray persistence begin disabled.

Disabling Gaming must not override Pause/Stop. Manual AI during Gaming is deferred unless the user explicitly disables Gaming for that action. No automatic game-process detection or game-setting changes in the MVP.
Target normal draining within 10 seconds; afterward show the blocker and safe wait/cancel options. Never blindly kill an in-flight writer, claim a partial backup succeeded, or promise measured FPS during transition. Preserve checkpoints and the last valid backup; communicate remaining activity honestly.

## Scheduling and reliability
Triggers: manual/once/daily/weekly, UTC storage and IANA time zones. Preview three occurrences before enablement. Jobs cannot run while the computer/application is off or asleep. Default missedPolicy=skip; alternatives coalesceLatest once within 24 hours or ask. No run-all burst or unbounded backfill. Default pending bounds: 100 global and 20 per automation; record overflow as aggregate missed counts.
Skip nonexistent DST wall times and execute only the first repeated local time. Recalculate after clock changes/sleep with watermarks and occurrence deduplication. Claim using transactions, unique occurrenceKey, leases, and atomic budget reservations.
At most three retries with backoff/jitter/Retry-After for known transient failures; obey current mode. Do not retry denied authorization, invalid schemas, or unknown external outcomes. Never claim universal exactly-once effects: prepare → call → reconcile/verify → complete; otherwise needsReview. Initial plan limits: eight steps, three tool rounds, 120-second AI timeout, one heavy worker, one concurrent AI request.
